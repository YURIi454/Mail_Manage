# Mail Manage — сервис почтовых рассылок

## Краткое описание

**Mail Manage** — веб-приложение для управления рассылкой писем. Пользователь создаёт
получателей и текст письма, собирает из них рассылку, задаёт период отправки и запускает
её. Сервис отправляет письма, фиксирует каждую попытку (успех/ошибка, ответ сервера,
время) и показывает статистику по работе с сервисом.

Основной сценарий работы — через интерфейс браузера; рассылку можно запустить и вручную
management-командой `start_spam_generator`. Дополнительно предусмотрены роль модератора
(менеджера), кеширование страниц и отправка писем по SMTP.

## Функционал

### Аккаунты

* Регистрация с подтверждением по e-mail (ссылка активации), вход/выход, восстановление пароля.
* Редактирование профиля, статусы пользователя (`активный`, `не активный`, `временный бан`,
  `бан навсегда`, `на удаление`), комментарий модератора.

### Роли

* **Пользователь** — работает только со своими данными (проверка владельца на уровне вьюх).
* **Модератор (группа `moderators`)** — видит все рассылки, получателей и попытки отправки,
  может отключать рассылки и редактировать статусы/комментарии пользователей.
* **Администратор** — все права, включая админ-панель Django.

### Рассылки

* CRUD для получателей, сообщений и рассылок (связи many-to-many), постраничный вывод списка рассылок.
* Поля периода `дата/время начала` и `дата/время окончания`; валидация дат в форме.
* **Динамический статус** рассылки (`Создана` / `Запущена` / `Завершена` / `Заблокирована`)
  вычисляется по текущему времени и флагу «отключена», не хранится в БД.
* Запуск рассылки из списка: проверка владельца и периода отправки, отправка писем
  каждому получателю, запись попытки с реальным ответом сервера.

### Статистика и отчёты

* Главная страница: всего рассылок, активных рассылок, уникальных получателей.
* Общая статистика: количество сообщений, рассылок, получателей, попыток, успешных и
  неуспешных отправок, процент успеха.
* Список попыток и страница подробностей каждой попытки (статус, время, ответ сервера).

____________________
* **Кеширование**: серверное (`django.core.cache`, `cache_page` + `vary_on_cookie`, чтобы
  страницы с пользовательскими данными не «протекали» между сессиями) и клиентское
  (`ConditionalGetMiddleware`). Инвалидация кеша — сигналами на изменение моделей.
* **Логирование** в `logs/debug.log`, почта через `django.core.mail` (SMTP либо console).
* **django-debug-toolbar** при `DEBUG=True`.

## Установка и запуск

### 1. Требования

* Python 3.13+
* PostgreSQL
* Poetry
* Redis — необязательно (нужен только при выборе Redis-бэкенда кеша)

### 2. Клонирование и зависимости

```bash
git clone <репозиторий>
cd Mail_Manage
poetry install
```

### 3. База данных

```sql
CREATE DATABASE mail_manage;
CREATE USER mail_user WITH PASSWORD 'your_password';
GRANT ALL PRIVILEGES ON DATABASE mail_manage TO mail_user;
```

### 4. Переменные окружения

Скопируйте образец и заполните значения:

```bash
# Linux / macOS
cp .env.sample .env

# Windows
copy .env.sample .env
```

| Ключ                                       | Назначение                                                                                         |
|--------------------------------------------|----------------------------------------------------------------------------------------------------|
| `SECRET_KEY`                               | секретный ключ Django                                                                              |
| `DEBUG`                                    | `True` / `False`                                                                                   |
| `HOST_NAME`                                | разрешённые хосты через запятую                                                                    |
| `NAME`, `USER`, `PASSWORD`, `HOST`, `PORT` | подключение к PostgreSQL                                                                           |
| `ATOMIC_REQUESTS`                          | оборачивать ли запрос в транзакцию (`True`/`False`)                                                |
| `CACHE_BACKEND`                            | `django.core.cache.backends.locmem.LocMemCache` либо `django.core.cache.backends.redis.RedisCache` |
| `REDIS_LOCATION`                           | адрес Redis, например `redis://127.0.0.1:6379/1`                                                   |
| `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`   | почтовый аккаунт для отправки писем                                                                |

### 5. Миграции и тестовые данные

```bash
poetry run python manage.py migrate
poetry run python manage.py add_all_data
```

`add_all_data` создаёт роли и тестовых пользователей:

| Логин (e-mail)   | Роль                              |
|------------------|-----------------------------------|
| `user1@user.com` | администратор (активен)           |
| `user2@user.com` | модератор (активен)               |
| `user3@user.com` | обычный пользователь (не активен) |

Пароль у всех тестовых аккаунтов — `password123`.

### 6. Запуск

```bash
poetry run python manage.py runserver
```

Приложение доступно на <http://127.0.0.1:8000/> (учтите, что при `DEBUG=False` нужно
добавить хост в `HOST_NAME`). Панель администратора — <http://127.0.0.1:8000/admin/>.

### 7. Тесты и линтер

```bash
poetry run python manage.py test
poetry run python manage.py check
poetry run ruff check . --select F,S,W,UP,I,B,C
```

> Полный `poetry run ruff check .` дополнительно прогоняет правила pydocstyle (D-правила)
> — по ним в проекте накоплен стиль-долг (отсутствующие докстринги и пробелы внутри
> докстрингов), он не нормализован.

## Отправка писем

По умолчанию в `config/settings.py` включён `console.EmailBackend` — письма
(включая ссылку активации при регистрации и письма рассылок) выводятся в консоль
сервера. Чтобы отправлять их реально, переключитесь на SMTP:

```python
EMAIL_BACKEND = 'django.core.mail.backends.smtp.EmailBackend'
```
